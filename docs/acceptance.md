# MuWeave 初始版本验收记录

本记录区分应用实现、技术测试和真实内容质量。模拟外部协议与合成视频不能证明实际供应商生成质量。

## 2026-11-03 本机验证结果

- Windows / Python 3.12：后端 41 项测试通过，包含真实 FFmpeg 探测与渲染。
- 前端 2 项客户端测试通过，TypeScript 检查和生产构建通过。
- Chromium 2 项端到端测试通过：中文文件保存、请求期间继续编辑、制作页面访问、两个镜头连续播放、时间线保存期间继续编辑。
- `uv run python scripts/smoke_export.py --duration 90` 实际输出时长为 `90.000000` 秒的有声 MP4、SRT 和制作记录。素材为本地合成画面与正弦音，不属于 AI 短剧质量验收。
- 本机进程内 TestClient 顺序读取同一剧本文件 200 次，p50 为 4.33ms、p95 为 5.44ms、最大 6.97ms。无并行生成负载，不包含浏览器、网络、模型推理或视频生成耗时，不作为跨机器性能承诺。
- GitHub CI 的远端状态单独核对；本机成功不能代替 Windows/Linux CI 成功。

## 本地验证命令

在仓库根目录：

```powershell
uv sync --locked
uv run pytest -q
uv run ruff check backend
uv run ruff format --check backend
npm --prefix frontend ci
npm --prefix frontend test
npm --prefix frontend run build
npm --prefix frontend run test:e2e
```

浏览器测试启动独立后端，数据写入被 Git 忽略的 `app-state/e2e`。运行测试前释放 8000 端口。测试不调用真实云端模型、不读取其他项目密钥、不修改参考资料仓库。

## 质量验收步骤

1. 在设置页创建实际文本、图片、视频供应商连接及模型配置。密钥仅在本机输入，存入系统凭据库。
2. 对文本模型执行“测试连接与工具”，再用写作/只读审稿任务检查真实文件调用质量。本机模型同样执行实际测试。
3. 生成并接受人物和场景参考图；通过视频模型生成至少两个包含真实对白的镜头。核对模型是否真的使用参考资产、生成原生音频。
4. 检查提交结果不确定时的供应商任务核对与续接、下载失败重试、应用正常重启续查。不要通过重复付费请求证明重试“成功”。
5. 预览多 take 并选择已接受版本，安排镜头与实际入出点，识别/编辑字幕并确认。
6. 完整预览并导出约 90 秒视频，检查人物连续性、对白、声音、字幕、切镜与中文字体。人工记录问题，不以接口成功代替内容合格。
7. 修改剧本或分镜，确认依赖素材标记需复核；只重做对应镜头，重新选用、复核字幕并导出。

## 已知边界与后续工作

- 当前是可运行的初始版本，不能标记整个第一阶段已验收完成。
- 机械校验目前覆盖 YAML 和基础项目结构；结构化人物/规则/伏笔的完整双向连续性、信息密度规则与 G1–G5 检查界面仍待完善。审稿可以读取原文，但结论须人工判断。
- 尚未实现自动两轮“写作—审稿—修订”编排；目前由用户发起写作、独立审稿和后续修订。
- 图片和视频使用 HTTP 模板；复杂签名、专有上传等协议需要专用适配器。原生 Anthropic/Google 工厂已提供，真实服务兼容性尚未验证。
- 独立 TTS/LipSync、背景音乐混音、图形化分镜板与专业剪辑功能尚未实现；当前分镜在项目文件中编辑，可让 Agent 拆镜。
- 文件修改提供哈希检查、快照和补偿恢复；不提供针对任意外部程序同时写文件的文件系统事务。历史与 SQLite 应随项目一起备份。
- 本地服务按单用户、单后端进程运行；当前不提供远程共享、多租户和多进程 worker。
- 前端编辑器按需加载，并只包含 Markdown/YAML 语言支持；Monaco 与 UI 基础库仍有较大构建块，冷启动体积有进一步优化空间。
- 尚无跨机器性能基线和真实供应商费用/成功率统计，不宣称当前实现是最快或生成质量最佳的方案。
